# Words Database Schema

This document describes the database schema for storing Hangman game words, tags, and their relationships in Supabase.

## Tables

### 1. `public.hangman_words`

Stores words for the Hangman game with difficulty values and locale information.

```sql
CREATE TABLE public.hangman_words (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  word TEXT NOT NULL,
  difficulty_value INTEGER NOT NULL CHECK (difficulty_value >= 1 AND difficulty_value <= 100),
  locale TEXT NOT NULL DEFAULT 'en',
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  CONSTRAINT words_word_locale_unique UNIQUE (word, locale)
);
```

**Fields:**
- `id`: Auto-incrementing primary key
- `word`: The word to be guessed (unique per locale)
- `difficulty_value`: Numeric difficulty from 1 (easiest) to 100 (hardest)
  - Easy: 1-33
  - Medium: 34-66
  - Hard: 67-100
- `locale`: Language code (e.g., 'en', 'es')
- `created_at`: Timestamp when the word was added

### 2. `public.hangman_tags`

Stores descriptive tags/hints for words.

```sql
CREATE TABLE public.hangman_tags (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  tag TEXT NOT NULL,
  locale TEXT NOT NULL DEFAULT 'en',
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  CONSTRAINT tags_tag_locale_unique UNIQUE (tag, locale)
);
```

**Fields:**
- `id`: Auto-incrementing primary key
- `tag`: Descriptive hint or tag text (unique per locale)
- `locale`: Language code (e.g., 'en', 'es')
- `created_at`: Timestamp when the tag was added

### 3. `hangman_word_tags`

Junction table linking words to their tags (many-to-many relationship).

```sql
CREATE TABLE hangman_word_tags (
  word_id BIGINT NOT NULL REFERENCES public.hangman_words(id) ON DELETE CASCADE,
  tag_id BIGINT NOT NULL REFERENCES public.hangman_tags(id) ON DELETE CASCADE,
  PRIMARY KEY (word_id, tag_id)
);
```

**Fields:**
- `word_id`: Foreign key to words table
- `tag_id`: Foreign key to tags table
- Composite primary key on (word_id, tag_id)

## View

### `hangman_words_with_tags`

A convenient view that returns words with their associated tags as an array in a single query.

**Schema:**
```sql
CREATE VIEW hangman_words_with_tags AS
SELECT 
    w.id,
    w.word,
    w.difficulty_value,
    w.locale,
    w.created_at,
    COALESCE(
        ARRAY_AGG(t.tag ORDER BY t.tag) FILTER (WHERE t.tag IS NOT NULL),
        ARRAY[]::TEXT[]
    ) as tags
FROM public.hangman_words w
LEFT JOIN hangman_word_tags wt ON w.id = wt.word_id
LEFT JOIN public.hangman_tags t ON wt.tag_id = t.id
GROUP BY w.id, w.word, w.difficulty_value, w.locale, w.created_at;
```

**Usage:**
```dart
// Fetch all words with tags in a single query
final response = await supabase
    .from('hangman_words_with_tags')
    .select()
    .eq('locale', 'en');

// Each row contains: id, word, difficulty_value, locale, created_at, tags[]
for (final wordData in response) {
  print('${wordData['word']}: ${wordData['tags']}');
}
```

**Benefits:**
- ✅ Single query instead of N+1 queries
- ✅ Better performance for fetching multiple words
- ✅ Tags are automatically aggregated as an array
- ✅ Empty tags array for words without tags

## Indexes

Performance indexes are created for common query patterns:

```sql
CREATE INDEX idx_words_locale ON public.hangman_words(locale);
CREATE INDEX idx_words_difficulty ON public.hangman_words(difficulty_value);
CREATE INDEX idx_words_locale_difficulty ON public.hangman_words(locale, difficulty_value);
CREATE INDEX idx_tags_locale ON public.hangman_tags(locale);
CREATE INDEX idx_word_tags_word_id ON hangman_word_tags(word_id);
CREATE INDEX idx_word_tags_tag_id ON hangman_word_tags(tag_id);
```

## Row Level Security (RLS)

### Policies

All tables have RLS enabled with the following policies:

#### Read Access (SELECT)
- **Authenticated users** can read all words, tags, and hangman_word_tags
- Public read access for gameplay

```sql
-- Words
CREATE POLICY "Anyone can view words"
ON public.hangman_words FOR SELECT
TO authenticated
USING (true);

-- Tags
CREATE POLICY "Anyone can view tags"
ON public.hangman_tags FOR SELECT
TO authenticated
USING (true);

-- Word Tags
CREATE POLICY "Anyone can view hangman_word_tags"
ON hangman_word_tags FOR SELECT
TO authenticated
USING (true);
```

#### Write Access (INSERT/UPDATE/DELETE)
- **No policies** for regular users
- Only migrations (or the service role) can modify data
- This ensures data integrity and prevents abuse

### Example: Adding a Word with Tags

```sql
insert into public.hangman_words (word, locale, difficulty_value)
values ('ELEPHANT', 'en', 50)  -- the trigger replaces difficulty_value
on conflict (word, locale) do nothing;

insert into public.hangman_tags (tag, locale)
values ('large mammal', 'en'), ('has a trunk', 'en')
on conflict (tag, locale) do nothing;

insert into public.hangman_word_tags (word_id, tag_id)
select w.id, t.id
from public.hangman_words w
join public.hangman_tags t on t.locale = w.locale
where w.word = 'ELEPHANT' and w.locale = 'en'
  and t.tag in ('large mammal', 'has a trunk')
on conflict do nothing;
```

Store words in uppercase; the app strips accents when it plays them.

## Difficulty Value System

The `difficulty_value` field is an integer between 0-100 representing word difficulty. This value is **automatically calculated** using a sophisticated algorithm.

### Automatic Calculation

Difficulty is calculated automatically based on three factors:

1. **Unique Letter Ratio (40%)**: Fewer repeated letters = harder
2. **Letter Rarity (35%)**: Uncommon letters = harder (language-specific)
3. **Word Length (25%)**: Longer words = harder

### Difficulty Categories

- **Easy (0-33)**: Short words, common letters, many repeats
- **Medium (34-66)**: Moderate length, mixed letter frequency
- **Hard (67-100)**: Long words, rare letters, few repeats

### Database Functions

#### Calculate Difficulty for Any Word
```sql
SELECT hangman_calculate_word_difficulty('DEVELOPER', 'en');
-- Returns: 0.58 (stored as 58 in difficulty_value)
```

#### Update All Word Difficulties
```sql
SELECT hangman_update_all_word_difficulties();
-- Recalculates difficulty for all words
```

#### Update by Locale
```sql
SELECT hangman_update_word_difficulties_by_locale('en');
-- Recalculates only English words
```

### Automatic Updates

Words automatically recalculate difficulty when:
- ✅ New word is inserted
- ✅ Existing word text is updated
- ✅ Word locale is changed

**Note:** See `DIFFICULTY_CALCULATION.md` for complete documentation on the difficulty algorithm, letter frequency tables, and customization options.

## Querying Examples

### Get random word by difficulty range
```dart
// Using the view for efficient single query
final response = await supabase
    .from('hangman_words_with_tags')
    .select()
    .eq('locale', 'en')
    .gte('difficulty_value', 34)
    .lte('difficulty_value', 66)  // Medium
    .limit(50);

// Response includes id, word, difficulty_value, locale, created_at, tags[]
```

### Search words by tag
```dart
// Option 1: Using view with text search (if tags is searchable)
final response = await supabase
    .from('hangman_words_with_tags')
    .select()
    .eq('locale', 'es')
    .textSearch('tags', 'animal');

// Option 2: Using joins (more precise control)
final tagResponse = await supabase
    .from('hangman_tags')
    .select('id')
    .ilike('tag', '%animal%');

final tagIds = tagResponse.map((t) => t['id']).toList();

final wordIds = await supabase
    .from('hangman_word_tags')
    .select('word_id')
    .in_('tag_id', tagIds);

final wordIdList = wordIds.map((w) => w['word_id']).toList();

final words = await supabase
    .from('hangman_words_with_tags')
    .select()
    .in_('id', wordIdList);
```

### Get word count by difficulty
```dart
final response = await supabase
    .from('hangman_words')  // Use words table for counts
    .select('difficulty_value', const FetchOptions(count: CountOption.exact))
    .eq('locale', 'en')
    .gte('difficulty_value', 1)
    .lte('difficulty_value', 33);
```

## Notes

- Words are stored in uppercase by the game logic (accent removal applied)
- The Ñ/ñ character is preserved (not converted to N/n)
- Each word-locale combination must be unique
- Tags can be shared across multiple words
- Deleting a word cascades to hangman_word_tags entries
- Deleting a tag cascades to hangman_word_tags entries
