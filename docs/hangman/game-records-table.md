## Table Name: `hangman_game_records`

### Existing Table Schema

Your Supabase table is already created with this structure:

```sql
CREATE TABLE hangman_game_records (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  user_id UUID NOT NULL DEFAULT auth.uid(),
  has_timed_mode_enabled BOOLEAN NULL,
  difficulty public.difficulty NULL,
  points BIGINT NULL,
  words BIGINT NULL,
  time_playing BIGINT NULL,
  CONSTRAINT records_pkey PRIMARY KEY (id),
  CONSTRAINT records_user_id_fkey FOREIGN KEY (user_id) REFERENCES auth.users (id)
) TABLESPACE pg_default;
```

### Required Indices

Run this SQL in your Supabase SQL Editor to create performance indices:

```sql
-- Create an index on user_id for faster user-specific queries
CREATE INDEX IF NOT EXISTS idx_game_records_user_id ON hangman_game_records(user_id);

-- Create an index on points for leaderboard sorting (descending)
CREATE INDEX IF NOT EXISTS idx_game_records_points ON hangman_game_records(points DESC);

-- Create an index on created_at for time-based sorting
CREATE INDEX IF NOT EXISTS idx_game_records_created_at ON hangman_game_records(created_at DESC);

-- Create a composite index for leaderboard queries by difficulty
CREATE INDEX IF NOT EXISTS idx_game_records_difficulty_points ON hangman_game_records(difficulty, points DESC);
```

### Database View with Usernames

Create a view that joins hangman_game_records with auth.users to fetch usernames:

```sql
-- Create a view that joins hangman_game_records with auth.users to get usernames
CREATE OR REPLACE VIEW hangman_game_records_with_usernames AS
SELECT 
    gr.id,
    gr.user_id,
    gr.created_at,
    gr.has_timed_mode_enabled,
    gr.difficulty,
    gr.points,
    gr.words,
    gr.time_playing,
    COALESCE(
        (au.raw_user_meta_data->>'username')::text,
        'Player'
    ) as username
FROM hangman_game_records gr
LEFT JOIN auth.users au ON gr.user_id = au.id;

-- Grant access to the view
GRANT SELECT ON hangman_game_records_with_usernames TO authenticated;
```

### Row Level Security (RLS) Policies

Enable RLS and create necessary policies:

```sql
-- Enable Row Level Security
ALTER TABLE hangman_game_records ENABLE ROW LEVEL SECURITY;

-- Policy: Users can only insert their own records
CREATE POLICY "Users can insert their own game records"
ON hangman_game_records FOR INSERT
TO authenticated
WITH CHECK (auth.uid() = user_id);

-- Policy: Anyone authenticated can view all records (for leaderboard)
CREATE POLICY "Anyone can view game records"
ON hangman_game_records FOR SELECT
TO authenticated
USING (true);
```

## Table Columns (`hangman_game_records`)

| Column | Type | Description | Constraints |
|--------|------|-------------|-------------|
| `id` | BIGINT | Primary key | Auto-generated (IDENTITY), NOT NULL |
| `created_at` | TIMESTAMP WITH TIME ZONE | When the record was created | NOT NULL, DEFAULT NOW() |
| `user_id` | UUID | Reference to auth.users | Foreign Key, NOT NULL, DEFAULT auth.uid() |
| `has_timed_mode_enabled` | BOOLEAN | Whether timed mode was enabled | NULLABLE |
| `difficulty` | public.difficulty | Game difficulty level (enum) | NULLABLE (values: 'easy', 'medium', 'hard') |
| `points` | BIGINT | Total score earned | NULLABLE |
| `words` | BIGINT | Number of words solved | NULLABLE |
| `time_playing` | BIGINT | Total seconds played | NULLABLE |

## View Columns (`hangman_game_records_with_usernames`)

The view includes all columns from `hangman_game_records` plus the `username`:

| Column | Type | Description | Source |
|--------|------|-------------|--------|
| `id` | BIGINT | Primary key | hangman_game_records.id |
| `user_id` | UUID | User reference | hangman_game_records.user_id |
| `created_at` | TIMESTAMP WITH TIME ZONE | Record creation time | hangman_game_records.created_at |
| `has_timed_mode_enabled` | BOOLEAN | Timed mode flag | hangman_game_records.has_timed_mode_enabled |
| `difficulty` | public.difficulty | Difficulty level | hangman_game_records.difficulty |
| `points` | BIGINT | Total score | hangman_game_records.points |
| `words` | BIGINT | Words solved | hangman_game_records.words |
| `time_playing` | BIGINT | Seconds played | hangman_game_records.time_playing |
| `username` | TEXT | Player's username | auth.users.raw_user_meta_data->>'username' (defaults to 'Player') |

## Row Level Security (RLS) Policies

The table has RLS enabled with the following policies:

| Action | Policy | Description |
|--------|--------|-------------|
| **INSERT** | Users can insert their own records | Users can only create records for themselves (`auth.uid() = user_id`) |
| **SELECT** | Anyone can view game records | All authenticated users can view all records (for leaderboard) |
| **UPDATE** | ❌ Not allowed | Game records are immutable (prevents tampering/cheating) |
| **DELETE** | ❌ Not allowed | Game records are permanent (maintains leaderboard integrity) |

The view `hangman_game_records_with_usernames`:
- ✅ **Anyone authenticated** can **SELECT** from the view
- ✅ Automatically joins usernames from `auth.users` metadata
- ✅ Returns 'Player' as default if username is not set

## Usage in Flutter

The `GameRecordService` class provides methods to interact with this table:

### Save a Game Record

```dart
final gameRecordService = GameRecordService();

final error = await gameRecordService.saveGameRecord(
  hasTimedModeEnabled: true,
  difficulty: 'medium',
  points: 250,
  words: 5,
  timePlaying: 180,
);

if (error != null) {
  print('Error saving game record: $error');
} else {
  print('Game record saved successfully!');
}
```

### Retrieve All Game Records (Leaderboard)

```dart
final gameRecordService = GameRecordService();
final records = await gameRecordService.getAllGameRecords(limit: 100);

for (var record in records) {
  print('${record['username']}: ${record['points']} points, ${record['words']} words');
}
```

**Note:** The `username` field is automatically fetched from `auth.users` via the database view, so you don't need to store it when saving records.

## Important Notes

- ✅ Table uses **BIGINT** for id, points, words, and time_playing
- ✅ The `user_id` is automatically set to `auth.uid()` on insert
- ✅ The `difficulty` field uses a custom enum type: `public.difficulty`
- ✅ Most fields are **NULLABLE** (except id, created_at, user_id)
- ✅ The view automatically fetches usernames from `auth.users` metadata
- ✅ Leaderboard queries are optimized with composite indices
- 🔒 **Game records are IMMUTABLE** - no updates or deletes allowed (prevents cheating)
- ⚠️ Make sure to handle NULL values when querying (use COALESCE or default values)

## Performance Considerations

- 📊 **Leaderboard queries** use `idx_game_records_points` for fast sorting
- 🔍 **User-specific queries** use `idx_game_records_user_id` for filtering
- 🎯 **Difficulty filtering** uses `idx_game_records_difficulty_points` composite index
- ⏱️ **Time-based queries** use `idx_game_records_created_at` for sorting
